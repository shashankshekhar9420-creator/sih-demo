## 6. Artisan API Handoff

Inspect the current handlers before modifying frontend requests.

| Endpoint | Request |
|---|---|
| `POST /api/catalogs` | JSON `{}`; alternatively multipart with three `images` entries |
| `GET /api/catalogs` | Returns `{ catalogs }` |
| `GET /api/catalogs/:id` | Returns `{ catalog }` |
| `POST /api/catalogs/:id/images` | Multipart: exactly three entries named `images` |
| `POST /api/catalogs/:id/process-images` | `{ images: [three saved raw paths] }` |
| `POST /api/catalogs/:id/transcribe` | Multipart: `audio1`, `audio2`, `audio3` |
| `POST /api/catalogs/:id/generate` | `{ englishTranslations, processedImages, category }` |
| `POST /api/catalogs/:id/price` | `{ materialCost, category, description, keywords }` |
| `PATCH /api/catalogs/:id` | Supported editable catalog fields |
| `POST /api/catalogs/:id/publish` | JSON `{}` |
| `GET /api/dashboard` | Returns `{ catalogs, orders, commerceAvailable, error? }` |

Important behavior:

- Successful mutations return `{ catalog, ...stepResult }`.
- DTO arrays/maps are parsed fields such as `rawImages` and `specifics`, not database `*Json` fields.
- Generation requires the exact saved translations and processed image paths.
- Pricing requires currently saved category, description, and keywords.
- Replacing images resets downstream work and stock.
- Retranscription resets generated content and pricing.
- Regeneration resets pricing.
- `READY` does not necessarily mean pricing and all publish prerequisites are complete.
- Publish failures preserve editable content.
- Demo transcripts are placeholders, not actual interpretations of recorded speech.

## 8. Known Risks To Address

### Inventory On Republish

Studio stock does not automatically decrease when a buyer purchases through Commerce. Republishing applies Studio’s absolute stock and can restore sold units unintentionally.

Preserve the specified publish contract, but make the behavior explicit and test it. Avoid introducing an unrequested inventory synchronization system without a deliberate design decision.

### Interrupted Processing

A crash after a catalog enters `PROCESSING` can leave it locked indefinitely. Review safe recovery for stale processing operations.

### Publication Display

Editing a published catalog changes its local status to `READY`, while the commerce listing remains live. Dashboard counts based only on `PUBLISHED` can therefore be misleading.

### Wizard Resume

Without matching browser-local progress, a priced catalog can resume directly at review and skip explicit stock confirmation. Ensure the stock step remains clear and intentional.

### Demo Security Boundaries

Studio has no authentication and exposes order information through its dashboard API. This is a controlled local prototype, not a public deployment. Do not expand the scope into production auth; clearly document the limitation.
